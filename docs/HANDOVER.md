- **画面収まり**: ゲームメニューが一画面に収まらず、スタートボタンとフッターが画面外だった。根本原因は幅の不具合: `.game-main` は CD 側 `.view`（flex column、height:100dvh）の子で、flex item に `margin: 0 auto` があると stretch が効かず、幅が fit-content → max-width の **480px に張り付いて**いた。480px 未満の画面では横にはみ出し（難易度タブやボタンの右端も切れた）、ジャケットが 332×414px になって縦も連鎖して溢れていた。修正: `.game-main` に `width: 100%` を明示し、メニューを縦 flex 化して高さ不足のときはカルーセル（ジャケット）だけが縮む構造にした。修正後ビルドで 360x800 / 412x915 / 390x844 / 360x740 / 360x640 / 430x932 の全サイズでフッターまで一画面に収まることを実測確認。**注意: この幅の不具合は共有モジュール由来で、テンプレート・NK-S003・NK-S007 にも同じ問題がある可能性が高い**（展開は未実施）。
- **端スワイプ「戻る」対策**: Android のジェスチャーナビゲーションの左右端スワイプ＝「戻る」が、端レーンを叩くときに発動してゲーム画面が閉じてしまう問題。端スワイプ自体は OS が最優先で処理するため止められないので、方針は「発動しても閉じずに中断になる」こと。実装（`src/game/game-main.ts`）: ゲームモード入場時に `history.pushState` で履歴を1つ積み popstate を捕捉する。プレイ中に「戻る」が発動したら遷移させず、演奏中なら `abort()` してゲーム内メニューへ戻し、履歴を積み直す。**解釈の明記: このゲームには「続きから再開できるポーズ」が存在しないため、「自動ポーズ」はバックグラウンド時（visibilitychange）と同じ中断（abort してメニューへ戻す）として実装した。再開可能なポーズが要る場合は別途の機能追加になる。** 本当にやめる操作（メニュー下部の「戻る」ボタンで CD 側へ出る）では、積んだ履歴を `history.back()` で取り消して通常の「戻る」に戻す（`src/main.ts` の `go()` に `exitGameMode()` フック。initGameMode の戻り値は `{ enter, exit }` になった）。入場時は `requestFullscreen` も試みる（非対応・拒否は無視。iPhone Safari 等では何も起きない）。履歴操作は try/catch で囲み、file: やサンドボックス環境では諦める。
