# START HERE（新作を作る人・AI へ）

このリポジトリは、デジタルCDシリーズの作品リポジトリです。新作は、このリポジトリをコピーして作ります。シングルの新作は最新のシングルのリポジトリを、アルバムの新作はこの NK-001 のリポジトリを起点にしてください。

仕組みは「エンジン」と「データ」の分離です。エンジン（`src/` のうち `src/album/` 以外など）には触らず、`src/album/` の中身を新しい作品の内容に差し替えて作ります。境目の詳細は `docs/PRODUCTION.md` の「エンジンとデータの境目」にあります。

## 読む順番

1. `docs/SINGLE.md` — シングル形態（デジタルシングルCD）の仕様。このリポジトリはアルバム形態で、シングル制作ではこちらが仕様の正本になる。
2. `docs/PRODUCTION.md` — 制作手順と、末尾の「運用ルール（引き継ぎ用）」。
3. `docs/HANDOVER.md` — この作品の現在地と経緯（状態・版数・残件）。
4. `CLAUDE.md` — アプリの技術方針。
5. `docs/` 配下の DESIGN-STUDY — ジャケット様式の判断材料（必要なとき）。

## オーナーとの分担

- 曲の生成はオーナーが自分の Gemini アプリ（AI Pro）で行い、チャットへ MP4 をアップロードして渡します。制作側は、受け取った素材から組み立てます。
- Gemini API で音楽生成はしません（API は音声合成専用というオーナー決定）。
- 確認ポイントは3か所（①組み合わせ・曲順、②表ジャケット候補、③歌詞の漢字の最終確認）ありますが、どれも進行を止める関門ではありません。確認が取れない場合は推奨案で進め、仮置きとして納品報告の仮置きリストに必ず残します。

## 作業場所と採番

- 作業フォルダは作品ごとに `~/workspace/` に作り（例: `single-nksNNN/`）、その中の `repo/` にリポジトリを置きます。
- アプリ ID は作品ごとに新規に付けます（`package.json` の `name`。既存作と重なると保存データやキャッシュが混ざります）。
- カタログ番号は、アルバムが NK-NNN、シングルが NK-SNNN の連番です。使用済みの番号は再利用しません。最新の採番状況は、デジタルCDダッシュボードの台帳で確認します。

## 環境の道具（この作業 VM）

- 文字起こしは `~/workspace/.asr-venv` の faster-whisper を使います。単語レベルの照合スクリプトは `~/workspace/album-nicholas-kiso/whisper_words.py`（引数は `ファイル.mp4:ja:novad` の形式）。
- 依存関係の修復スクリプトは `~/workspace/.nk-test/` にあります（使い方は `docs/PRODUCTION.md` の「運用ルール」が正本）。

## 仕上げ

- 公開したら `docs/HANDOVER.md` を最新の状態に更新します（古い内容は残さず、今の状態だけを書く）。
- シリーズ全体の現況はデジタルCDダッシュボードに集約されます。HANDOVER には、このリポジトリ側の事実（URL・版数・収録・残件）を正確に残してください。
